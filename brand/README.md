# Grit Chat brand

Every asset in `logo/` and `icon/` is generated by `tools/build.mjs` from font metrics and a stated
spacing spec. Nothing here was drawn by hand and nothing came out of an image model. To rebuild:

```
cd brand && npm install && npm run build
```

To look at the result, which you should do before trusting any of it:

```
node tools/proof.mjs      # writes brand/proof/index.html
```

## Sabotage-testing a generator: restoring the tool does not restore the output

Everything here is generated, and that changes how you prove a check works. The normal drill is to
break an input, watch the check go red, restore, and confirm the tree is clean. For a **checker**
that is enough. For a **generator** it is not, and the gap has already cost one near miss.

While proving that `site/scripts/fonts.mjs` really drops the trademark codepoints, the drop list was
edited and the generator re-run. That regenerated four shipped `woff2` files **carrying a registered
sign**. Restoring `fonts.mjs` restored the tool and left the poisoned artifacts on disk, and because
the script was clean again, nothing pointed at them. The restored script is exactly the evidence that
makes you stop looking.

So: **restoring a generator is the source file AND a regeneration, and the evidence is a diff of the
outputs, not of the tool.** Restoring the tool and re-running the tool are different acts, and only
the second one produces evidence. In practice, after sabotaging any generator here:

```
git status --porcelain          # generated assets must not appear
git diff --stat -- <outputs>    # and must be byte identical, not merely present
```

A useful side effect of doing that: the byte-identical restore also established that these generators
are **deterministic**, which nothing had previously proven. Same inputs, same bytes, so a drifted
asset in a diff is a real signal rather than compression noise.

The same hazard applies to `tools/build.mjs`, `site/scripts/favicons.mjs` and the app icon rasters:
each writes committed files, so each can be left sabotaged by a test that looks like it passed.

## The two documents

There are two, they answer different questions, and confusing them is how this file ended up titled
"brand brief" for a while when it is nothing of the kind.

**This file is the GUIDE.** Marks, sizes, palette, type specimen, clear space, do-nots. It answers
"how do I set this correctly".

**`BRIEF.md` is the BRIEF.** What the product is, who it is for, and why every visible decision went
the way it did. It answers "why is it like this at all", which is the question a specimen sheet
cannot answer and the one that governs the next decision.

Both build to a single shareable file. Run them **from the repository root**, not from `brand/`,
because both resolve paths from there and reuse the site's own subset fonts:

```
node brand/tools/brief.mjs        # writes brand/brief.html            the guide
node brand/tools/brief-doc.mjs    # writes brand/grit-chat-brief.html  the brief
```

Each renders its markdown with the marks and the type inlined, and it is the file that goes out as a
link. Both have to be genuinely self-contained: they are read in an isolated frame with no network
access, where a CDN font or a remotely referenced image renders as nothing rather than failing
loudly. So every face is embedded as a data URI, every mark is embedded as SVG markup, and the
generator asserts that before it will write the file. Both refuse to emit a script tag, so the
documents are inert by construction.

Assert is not the same as prove, so audit the output too. `site/tools/inline.mjs --check` decodes
every payload and checks it against the format it claims to be, which is the one thing a reference
spelled `data:` cannot tell you:

```
(cd site && node tools/inline.mjs --check ../brand/brief.html)
(cd site && node tools/inline.mjs --check ../brand/grit-chat-brief.html)
```

The shared look lives in `tools/doc-style.mjs`, so the two documents cannot drift into two
typographic systems. All three outputs, `brief.html`, `grit-chat-brief.html` and `proof/`, are
derived and are not committed, because between them they are most of a megabyte of base64 that a one
line command regenerates.

## The identity is a wordmark, and that was a decision

There is no pictorial symbol. This is deliberate.

An earlier attempt built a mark out of the app's own hop-trace geometry: the run of node glyphs,
connectors and terminal cap that renders under every message to show the route it physically took.
The reasoning was sound, the mark was original, and it was constructed rather than generated. It also
read as a robot arm. That is fatal rather than fixable: a symbol people misread on first sight has
failed, and you cannot explain your way out of a symbol.

So the identity is carried by the letterforms. That is a real discipline, not a lesser option. It
means the type choice, the spacing and the optical corrections do all the work, and there is nowhere
to hide. A symbol has to earn its existence, and this one did not.

## Type, committed

**Barlow Condensed Bold, all capitals.**

Barlow Condensed is already the app's display face, chosen in `src/design/tokens.ts` because Barlow is
drawn from California public signage: tall condensed capitals that stay legible on a sunlit highway.
That is the literal reading condition for this product, which is used outdoors, in dust, at arm's
length, sometimes with gloves on. A logotype that matches the interface it labels is one less thing to
explain, and the register is right: condensed caps is how field equipment is marked.

Capitals rather than mixed case because condensed lowercase was tested and came out cramped. It gave
up the signage authority without buying real warmth. Rendered comparisons are in the notes below.

The name is two words of four characters that both end in T, which is what makes the compact stack
possible at all.

## Optical letterspacing, computed

A font's built-in sidebearings are tuned for running text at reading size. A logotype is nine
characters at display size, read once, and the eye is unforgiving: metric spacing leaves a hole after
a diagonal like A and jams a pair of flat stems like I and T.

`tools/typeset.mjs` measures each glyph's own white space and gives every glyph the sidebearings that
equalise its margins. The method, which is the classic one:

1. Look only inside the band the eye judges, baseline to cap height for capitals.
2. Walk scanlines across that band and record where each glyph's ink actually starts and ends. This
   is the silhouette, not the bounding box, which is the point: a bounding box cannot tell A from H.
3. For each side, average how far the ink recedes from its own extreme. That is the white the glyph
   already carries. Recession is clamped at `maxDepth`, because the deep inside of a C is not white
   that touches its neighbour, and letting it count would blow the C wide open.
4. Give each side the sidebearing that brings its total white to one target.

Two knobs, both stated rather than hidden: `target` is the white every glyph side is brought to, as a
fraction of cap height, and it is the overall tightness of the logotype. `maxDepth` is how deep a
counter may count as neighbouring white.

What that produces for GRIT CHAT, at cap height 100:

| glyph | ink width | carries left | carries right | left sidebearing | right sidebearing | gap before |
|---|---|---|---|---|---|---|
| G | 57.0 | 2.42 | 6.84 | 5.38 | 0.96 | 0.00 |
| R | 58.1 | 0.01 | 5.72 | 7.79 | 2.08 | 8.75 |
| I | 20.1 | 0.01 | 0.01 | 7.79 | 7.79 | 9.87 |
| T | 60.0 | 16.23 | 16.82 | -8.43 | -9.02 | -0.64 |
| C | 57.0 | 2.52 | 15.78 | 5.28 | -7.98 | 26.26 |
| H | 56.0 | 0.01 | 0.01 | 7.79 | 7.79 | -0.19 |
| A | 65.1 | 10.55 | 10.54 | -2.75 | -2.74 | 5.04 |
| T | 60.0 | 16.23 | 16.82 | -8.43 | -9.02 | -11.17 |

Read that as the method working. `I` and `H` are plain stems, carry no white of their own, and get the
full 7.79 target on both sides. `T` carries 16.8 under its arm and goes negative, so its neighbours
tuck underneath. `A` carries 10.5 on both diagonals. The classic loose pair, A followed by T, closes
to -11.17 with no hand kerning anywhere in the system.

The word space between GRIT and CHAT is 26.26 rather than the nominal 30, because T's arm overhangs
into the gap and the gap is measured, not assumed.

## The app icon is a lettermark, and the favicon is a different one

A wordmark cannot be an app icon. At 60 by 60 points, GRIT CHAT is unreadable. So the icon is a
lettermark cut from the same face, which keeps it in the family and invents no new symbol.

**App icon: GC.** Two letters are more specific than a lone G, which is a crowded letter. At 1.11:1 it
is also the squarest of the candidates tested, and the guaranteed Android zone is a circle, so
squarest fills the most area. Measured: GC fills 46.6 by 41.9 inside Android's 66dp circle, against
32.1 by 57.7 for a lone condensed G.

**Favicon: G alone.** Rendered at 16px and inspected at 4x, GC merges into one dark smudge as the
counters close up. A lone G stays unambiguous. An app icon is never shown below 29px so it can afford
both letters; a favicon has to survive 16, so it gets the cut that works there. Same face, same
colours, so it still reads as the same brand.

**The field is sodium, not dusk.** Sodium `#F2A93B` is the product's one loud colour, reserved in the
app for a primary action and a live relay, which is to say a human burning electricity for someone
else. Dark icons were rendered against a simulated home screen next to saturated neighbours: they
read as restrained at 180px and disappeared at 40px. On a home screen the field carries more identity
than the letters do. An icon is an invitation to act, so spending the action colour on it is
consistent rather than a violation of the app's rule.

### Platform safe zones, checked rather than assumed

**Android adaptive icons.** Both layers are 108dp square. The system may mask down to 72dp, and only a
centred **66dp circle** is guaranteed visible across every OEM mask shape. So the safe zone is 61.1%
of the width, and it is a circle, not a square. The lettermark is fitted to that circle at 0.95, five
percent back from the boundary, because sitting exactly on a guaranteed-visible line is a bad place to
be when the guarantee is somebody else's mask.

**iOS.** Submit a square with ninety degree corners. The mask is a continuous-corner squircle whose
effective radius sits near 22.37% of the width; Apple does not publish the curve. `tools/masks.mjs`
therefore checks clearance against both a superellipse approximation and a plain rounded rect at
22.37%, and the glyph has to clear the harsher of the two. It does: 635 by 571 in a 1024 square.

Verified by rendering the icon under every Android mask shape (circle, squircle, rounded square) and
both iOS approximations, at 180, 120, 60, 40 and 29 pixels. Legible at all of them.

## Contrast, computed not asserted

WCAG 2.x relative luminance, from `tools/contrast.mjs`. Thresholds: 4.5:1 normal text, 3:1 large text
and non-text components, 7:1 AAA normal text.

| pair | ratio | verdict |
|---|---|---|
| wordmark, alkali on abyss | 16.41:1 | AAA |
| wordmark, alkali on night | 15.24:1 | AAA |
| wordmark light, night on alkali | 15.24:1 | AAA |
| body text, alkali on night | 15.24:1 | AAA |
| wordmark, alkali on surface | 14.02:1 | AAA |
| accent, sodiumBright on night | 12.14:1 | AAA |
| icon, night on sodium | 9.23:1 | AAA |
| accent, sodium on night | 9.23:1 | AAA |
| secondary text, dust on night | 8.62:1 | AAA |
| stack CHAT muted, dust on night | 8.62:1 | AAA |
| delivered, sage on night | 8.07:1 | AAA |
| failure, emberBright on night | 6.74:1 | AA |
| hint, alkaliFaint on night | 5.76:1 | AA |
| failure, ember on night | 5.24:1 | AA |
| on sodium fill, sodiumDeep | 4.76:1 | AA |

All 15 pairs pass. Four did not over the course of this work, in two rounds.

**Round one.** `alkaliFaint` was `#7E7A6D`, 4.30:1 on night and therefore below AA for normal text,
and `tokens.ts` assigns it to hints, disabled states and timestamps. A timestamp is normal-size text,
so every timestamp in the app was below AA. `sodiumDeep` was `#6B4A16`, 4.02:1 on a sodium fill, so a
button label on amber was below AA too. Both were found by computing the whole matrix rather than by
inspection.

**Round two**, on the app branch, which checked all 52 pairs rather than the 15 here and solved each
token against the WORST surface it actually sits on rather than a nominal one. `alkaliFaint` landed at
`#939083`: 4.71:1 on `raised`, which is outbound bubbles and the composer, then 5.05 on surface, 5.76
on night, 6.20 on abyss. `sodiumDeep` landed at `#5D4012`: 4.76:1 on a sodium fill, 6.26 on
`sodiumBright`. `raisedHigh` `#2D3148` was deleted rather than fixed, because it was documented as the
focus ring colour at 1.44:1 and nothing used it; a token whose comment tells you to use it for
something it cannot do is a trap. Boundaries that carry meaning use the new `edge` token, measured for
that job at 3.13:1 on raised.

**Where these numbers come from, and which copy wins.** This table is a SNAPSHOT of
`src/design/tokens.ts`. It is not the source of it. The app is where the values are consumed, and
`__tests__/contrast.test.ts` computes every pair from those tokens and fails when one drops below its
standard, so the app's numbers are enforced and this document is a picture of them. A hand-maintained
table must never be treated as authoritative over a tested constant, whichever one happens to be
correct on a given day.

So if this table and `src/design/tokens.ts` disagree, **the app is right and this table is stale.**
Regenerate it rather than editing the app to match it.

It cannot drift silently any more, which is the actual fix. `tools/build.mjs` used to carry a
hand-written copy of the palette, and that copy went stale exactly the way a hand-written copy does:
it sat on the round-one values after the app had moved to round two, and since `brand.json` and this
table are generated from it, and `brief.html` is generated from this file, the stale copy would have
published a document stating ratios for values the product no longer used. The palette is now READ out
of `src/design/tokens.ts` at build time, and the extraction is guarded: a renamed or missing token
throws rather than producing an empty palette. That guard fired on its first run, which is how it is
known to work.

## Using it

**Clear space** is half the wordmark's cap height on all four sides. The SVG viewBox already carries a
small internal pad, so clear space is measured from the ink, not the file edge.

**Minimum sizes**, each verified by rendering and looking, not estimated:

| asset | minimum | note |
|---|---|---|
| wordmark | 14px rendered height | legible at 14, comfortable at 16. Below 14 use the lettermark. |
| compact stack | 44px | it dies below roughly 40px, since each line is half the height |
| lettermark | 20px | |
| app icon | 29px | the smallest size iOS renders |
| favicon | 16px | which is why it is a single letter |

**Do not**: recolour the wordmark outside the palette, add a symbol beside it, outline or shadow it,
stretch it non-uniformly, set the name in any other face, or reintroduce a pictogram. Do not put a
trademark symbol on anything: see below.

**On light grounds** use the light treatment or set `currentColor` to night `#12131F`. Alkali on white
is not a legible combination and is not a supported treatment.

## Trademark

"Grit" is **not** cleared. There is a live Class 38 registration held by Grit Media LLC covering
television broadcasting, a Garmin Class 9 mark for athletic training software, and a mobile game
called Team Grit. No messaging app named Grit exists in either app store. No trademark opinion has
been obtained.

So: no `(R)`, no `(TM)`, no trademark symbol anywhere, and nothing that implies the mark is
registered. Every user-visible product string lives in one module, `src/branding.ts` in the app and
`site/src/branding.ts` on the site, so a rename stays cheap. The wordmark is the only asset that
encodes the name, and it is regenerated from one string in `tools/build.mjs`.

## Directions that were rejected, and why

Kept because the comparison is the argument for what shipped. Regenerate with
`node tools/directions.mjs` and `node tools/explore2.mjs`, then look at `brand/explore/`.

| direction | why not |
|---|---|
| Hop-trace pictorial mark | Read as a robot arm. Fatal, not fixable. |
| Condensed Bold, mixed case | Condensed lowercase came out cramped. Lost the signage authority without gaining warmth. |
| Barlow Bold, mixed case | Genuinely good and the most legible at small sizes, but the most generic: it could be any app. Kept as the runner up. |
| Barlow Bold, capitals | Solid, and wide enough to eat horizontal space in a nav. Less characterful than the condensed cut. |
| IBM Plex Mono | Reads as a developer tool, which is wrong for a consumer messenger. Also fights the optical pass, which reads mono's large built-in sidebearings as carried white and strips them. |
| G over C stacked icon | 0.28:1, so it fits only 17.9 by 63.5 inside the Android safe circle. An illegible smudge at 40px. |
| Lone G icon | Works, but G is a crowded letter and says less than GC. Retained for the favicon only, where 16px forces it. |
| Justified stack as primary | Loses legibility below roughly 40px, and the tracking GRIT needs to match CHAT's width is visible. Retained as a compact secondary. |
